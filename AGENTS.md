# Project Context & Agent Memory (`AGENTS.md`)

## 1. Executive Summary & Context

- This is a Bun-workspace monorepo for Crashed NIS, with a Vite + React frontend and a Hono API deployed to Cloudflare Workers.
- The backend is a clean-room NIS authentication service using standard TypeScript, native Promises, and `ky`. Earlier Next.js and Effect-based directions have been superseded.
- **Effect is completely removed from this project.** Do not add Effect or Effect-derived packages, APIs, patterns, or dependencies.
- Bun is the package manager, development toolchain, and test runner. Production API code runs on Cloudflare Workers and must not depend on Bun or Node-only APIs.

## 2. Tech Stack & Environment Standards

- **Monorepo / Package Manager:** Bun Workspaces (`apps/*`, `packages/*`) + Turborepo. Use the root `dev`, `build`, `lint`, `format`, `test`, and `typecheck` scripts; `bun.lock` is authoritative.
- **Backend Runtime:** Hono on Cloudflare Workers (`apps/api`). Use Worker bindings generated by Wrangler and Web Platform APIs supported by Workers.
- **Frontend:** Vite + React + TypeScript (`apps/web`).
- **Shared UI:** shadcn components and shared theme styles live in `packages/ui` (`@crashednis/ui`); apps consume its explicit package exports.
- **API documentation:** `apps/api` serves its OpenAPI 3.1 document at `/openapi.json`; the web app hosts Scalar at `/docs`.
- **HTTP client:** **HTTP requests MUST use `ky` (`apps/api/src/shared/http/client.ts`).** Keep the NIS-specific defaults centralized there.
- **Code style:** Use standard TypeScript `async`/`await`, native Promises, and custom typed error classes. Do not use Effect or monadic wrappers.
- **Formatting & Linting:** `oxfmt` and `oxlint`.
- **Testing:** `bun:test` for API/backend behavior using in-memory Hono `app.fetch(new Request(...))`; Vitest + `happy-dom` for frontend UI.
- **Manual API requests:** Keep requests as plain-text Bruno `.bru` files under `apps/api/bruno/`, committed with code. Do not require cloud-hosted API collections.
- **Build and type safety:** Use `tsc --noEmit` and Wrangler dry-run builds. Turbo orders builds and typechecks after workspace dependency builds.

- `apps/api/src/index.ts` mounts the auth router under `/api/v1/auth` and exports the Hono app type.
- The Worker exposes `/health` for direct Worker/Bruno health checks and retains `/api/health` for frontend-proxied access. Only `/api/health` is documented in OpenAPI so Scalar requests go through Vite/Pages `/api/*` routing rather than the web app's `/health` path.
- API TypeScript alias: `@/*` maps to `./src/*` in `apps/api/tsconfig.json`. TypeScript 7 has removed `baseUrl`; preserve the alias without that option.
- Cross-workspace contracts live in `packages/types` (`@crashed-nis/types`); shared compiler settings live in `packages/tsconfig`.
- `worker-configuration.d.ts` is generated from Wrangler configuration. Run `bun run --cwd apps/api typegen` after changing bindings; do not hand-maintain duplicate binding definitions.
- The shadcn monorepo setup uses matching `components.json` files in `apps/web` and `packages/ui`. Generate shared UI components into `packages/ui`, import them through `@crashednis/ui/components/...`, and keep app-only components under `apps/web/components`.
- `packages/ui` exports TypeScript source for Vite to consume directly; it does not need a separate JavaScript build step. Its `typecheck` script validates the shared components.
- Shared Tailwind v4 theme CSS lives at `packages/ui/src/styles/globals.css` and is imported by `apps/web/src/main.tsx`. Its `@source` directive scans shared UI components; keep it when adding component files that use Tailwind classes.
- UI-only runtime dependencies belong in `packages/ui/package.json`; React and React DOM are peer dependencies. Use the shared `cn` helper from `@crashednis/ui/lib/utils`.
- Vite proxies `/api/*` to `BACKEND_URL` (default `http://localhost:8787`) without changing the path, because every documented API operation is mounted under `/api` on the Worker. Production Pages requests use `apps/web/functions/api/[[path]].ts` and the `API` service binding in `apps/web/wrangler.jsonc`, which also forwards the original request path to `crashed-nis-api`.
- Copy `apps/web/.env.example` to `apps/web/.env.local` to point Vite at a non-default local API server; do not expose `BACKEND_URL` as a `VITE_` client variable.
- API auth cookies are `Secure`, so device testing (iOS Safari on the LAN) requires `bun run --cwd apps/web dev:https` — Vite serves via a self-signed cert (`@vitejs/plugin-basic-ssl`, enabled when `HTTPS=true`) and the device must accept the certificate warning; desktop browsers keep Secure cookies on plain-HTTP `localhost`, so plain `dev` remains fine there. Never weaken the cookie `secure` flag for development.
- Scalar is lazy-loaded on `/docs` and fetches the relative `/api/openapi.json` URL so local and Pages routing use the same spec path. Keep its CSS layer order declared before the Tailwind import in the shared stylesheet.
- Do not replace the Pages Function with an external `200` rule in `_redirects`: Cloudflare Pages `_redirects` only supports proxying relative URLs. Keep the Pages service binding as the production edge proxy.

## 4. Strict Code Conventions & Design Rules

- **Language:** All code, comments, logs, and user-facing messages must be in English.
- **HTTP calls:** Always use the configured `ky` instance from `apps/api/src/shared/http/client.ts` for outbound HTTP requests. Do not use raw `fetch` directly in services or routes. The configured client uses a 30-second timeout, two retries for GET/POST and selected transient statuses, `User-Agent: Dart/3.1 (dart:io)`, and `Cookie: Culture=ru-RU;`.
- **Async and errors:** Use ordinary `async`/`await` and Promises. Domain failures use custom classes extending `Error`; handle expected cases explicitly and return a generic service error for unexpected upstream/runtime failures. Do not reintroduce Effect.
- **Validation:** Validate untrusted login request bodies with typed parsers. **Third-Party API Type Handling:** Do NOT strictly validate external NIS microservice responses at runtime with strict schema parsers. Use standard TypeScript interface casting via `ky.json<T>()` or permissive types. Allow extra response properties to pass through silently so third-party schema updates do not break application runtime execution. Use optional chaining for upstream fields that may be absent.
- **Type safety:** No `any` and no non-null assertions (`!`). Prefer narrowing and explicit types over unsafe casts.
- **Worker compatibility:** Use Fetch/Web Crypto and supported Web APIs. Never import Node-only or Bun runtime APIs into deployed code. Keep request state local to each request and use generated typed bindings.
- **Authentication behavior:** Validate login input before upstream calls; match application type `52` to the contingent `School.Gid`; derive the city from the matched JCE URL; and issue HTTP-only, Secure, SameSite Lax cookies whose max-age is bounded by JWT expiry and configured lifetime.
- **Security controls:** Apply Hono `secureHeaders` globally with `X-Frame-Options: DENY` and `X-Content-Type-Options: nosniff`; configure CORS with explicit frontend origins and credentials, never a wildcard; and enforce a Cloudflare rate-limit binding on authentication routes.
- **Request validation:** Validate every POST/PUT request body with Zod and `@hono/zod-validator`; keep input constraints explicit, including the 12-digit IIN regex.
- **Git-native API testing:** Manual requests must be version-controlled `.bru` files in `apps/api/bruno/`. Automated API integration tests must use `bun:test` and in-memory `app.fetch(new Request(...))` under `apps/api/tests/`; do not open ports or rely on a live server. Do not require proprietary Postman cloud workspaces or unversioned environments.
- **Secrets and observability:** Never commit secrets; configure them with Wrangler secrets. Keep compatibility dates current and enable Worker logs and traces for production.
- **Keyboard shortcuts (Hotkeys):** All keyboard shortcuts MUST use `@tanstack/react-hotkeys` (`useHotkey`/`useHotkeys`, `@tanstack/react-hotkeys` React adapter for `@tanstack/hotkeys`), never raw `keydown` listeners. Register each hotkey inside the component that owns the action, use typed chord/sequence strings, and attach `meta` (name/description/group) so devtools and a future cheat sheet can list them. Sequences follow the `G`+`key` pattern: `G J` opens Журнал (`/`), `G R` opens Табель (`/reports`), `G S` opens Настройки (`/settings`), `G P` opens Прогноз (`/predict`), registered in `apps/web/components/dashboard-layout.tsx`; on desktop (`lg`) each rail link shows the chord as a `KbdGroup` of `Kbd` chips (`hidden lg:ml-auto lg:inline-flex` in `packages/ui`'s `kbd`), hidden on mobile. Extend this pattern for every new keyboard-friendly action.
- **Zustand:** Client-side UI state that must survive reloads lives in Zustand stores under `apps/web/lib/stores/` configured with the `persist` middleware (localStorage, storage keys prefixed `crashed-nis-`: `crashed-nis-journal` for journal sort/filters, `crashed-nis-settings` for grade-color thresholds). Server data stays in SWR (`useApiSWR`); never duplicate API state into Zustand. The active journal quarter stays in the URL search params, not the store.
- **Phosphor icons:** Every `@phosphor-icons/react` import and JSX tag MUST use the exported `Icon` suffix (`MoonIcon`, `SortAscendingIcon`), never the bare aliases (`Moon`, `SortAscending`).
- **UI/UX guidance:** Always run `bunx --bun ui-skills` for UI/UX information (route via `ui-skills start`/`list --category`, load only the smallest useful skill, max 3; e.g. `fixing-accessibility` for interactive controls, dialogs and focus rules).
- **Keyboard accessibility (no-mouse):** Every page must be fully operable without a mouse — no exceptions and no partial states. Use the `frontend-a11y` skill (`.agents/skills/frontend-a11y`) whenever writing or reviewing markup/components: native elements and semantics first, no redundant ARIA or `title` attributes, no `aria-label` on roleless elements that would hide visible content (use `sr-only` text instead), and always real `<button>` roots for clickable cards. The journal index page is the reference implementation (native `ul`/`li` grid, tabbed quarters via arrow keys, keyboard-openable dropdowns — Base UI Menu/Tabs/Slider already carry the keyboard wiring; subject cards form a roving-tabindex grid, one Tab stop for the whole list with arrow-key movement respecting the column layout; rubric modal on `?subject=` closes with Escape/Back and traps focus).
- **Validation:** For API changes run API typecheck, tests, lint, and Wrangler build. For cross-workspace changes run root `bun run typecheck`, `bun run test`, `bun run lint`, and `bun run build`.

## 7. Security Policies

- Every POST and PUT route must validate its request body using Zod and `@hono/zod-validator`; apply strict format constraints to identifiers and credentials.
- Configure CORS with explicit allowed frontend origins and `credentials: true`. Never use wildcard origins for credentialed APIs.
- Apply `secureHeaders()` globally. Preserve at least `xFrameOptions: 'DENY'` and `xContentTypeOptions: 'nosniff'`.
- Authentication endpoints must use Cloudflare's Worker Rate Limiting binding keyed by a trusted client IP header (`cf-connecting-ip`), with the login limit set to five requests per minute. Keep its Wrangler binding and generated Worker types in sync; select a namespace ID unique within the Cloudflare account.
- All authentication cookies must explicitly use `httpOnly: true`, `secure: true`, `sameSite: 'Lax'`, and `path: '/'`; token expiry may further constrain their `maxAge`.
- Automated tests should cover allowed and rejected CORS origins, security headers, rate-limit behavior, input validation, and cookie flags.
